# HFPager-совместимый пейджер для Windows (экспериментальный)

Файлы: `hfpager_app.py` (окно программы), `hfpager_rx.py` (приёмник с АПЧ), `hfpager_modem.py`
(кодек протокола и передатчик), `HFPAGER_PROTOCOL.md` (описание формата).

## Запуск
1. Установите Python 3.10+ для Windows (с галочкой «Add to PATH» и компонентом tcl/tk).
2. Дважды щёлкните `run_hfpager.bat` (он поставит `numpy` и `sounddevice` и запустит программу)
   или выполните `py -m pip install -r requirements.txt` и `py hfpager_app.py`.
3. Отдельный `HFPagerApp.exe`: запустите `build_exe.bat` на Windows (нужен интернет для установки PyInstaller).

## Как пользоваться
* **Мой ID** – ваш собственный номер станции (0…65535); он попадает в поле «отправитель».
* **Вход / Выход** – звуковые устройства: вход принимает звук от приёмника, выход подаётся на
  микрофонный/линейный вход трансивера (SSB). Для лучшей работы – внешний USB-интерфейс,
  отключите «улучшения звука» Windows, частота дискретизации 48000 Гц.
* **Кому (ID)** + поле текста + **Отправить** (или Enter). Текст до 252 байт (кодировка Windows-1251).
* **Скорость** 5.86 или 23.44 Бод для передачи; приём распознаёт обе автоматически.
* **Тон 0, Гц** – частота нулевого тона (группа из 18 тонов занимает ~200 Гц на 5.86 Бод и ~400 Гц
  на 23.44 Бод). **Уровень TX** держите таким, чтобы не было ALC-ограничения. **Задержка PTT/VOX** –
  пауза перед сигналом, чтобы трансивер успел перейти на передачу (VOX). Управления PTT по
  COM-порту в этой версии нет.
* **Порог приёма, дБ** – превышение «остроты» спектра над шумом для обнаружения сигнала (по умолчанию 4).
* В окне обмена показываются все принятые кадры: зелёным – адресованные вам, фиолетовым – маяки,
  серым – повторы.

## АПЧ (автоподстройка частоты)
Приёмник сам находит группу тонов в звуковом спектре (настройка по частоте не нужна), по
преамбуле определяет положение нулевого тона и далее отслеживает по каждому символу уход частоты
(контур первого порядка); при неудаче пробует другие коэффициенты слежения, сдвиги фазы символов
и поправку на расхождение частот дискретизации. В тестах декодируются кадры при расстройке
по частоте, дрейфе, скачках на полтона и расхождении тактов звуковых карт до ±300 ppm.
Флажок «АПЧ» можно отключить (останется приём по разностям тонов).

## Проверено / не проверено
* Проверено: кодек на 47 записях 5.86 Бод и 5 записях 23.44 Бод; поток из реальных записей;
  синтетика с шумом (декодирование до ≈ −6 дБ ОСШ в полосе 2.7 кГц на 5.86 Бод) и без ложных
  срабатываний на шуме; передача→приём «через петлю» с имитацией звуковой карты.
* **Не проверено:** интерфейс запускался только с имитацией tkinter (без настоящего экрана Windows),
  работа с реальной звуковой картой и трансивером, совместимость в эфире с оригинальным приложением.
* Подтверждения доставки: приём ACK-кадров и отметка «доставлено» работают; автоподтверждение
  (флажок «Автоподтверждение (экспер.)») построено по одной записи ответа и совместимость с оригиналом в эфире
  не проверена; NAK не реализован.
* Не реализовано: скорость 1.46 Бод, GPS,
  CW-позывной маяка, управление PTT.

Передача в эфир на КВ требует лицензии радиолюбителя.

## Интерфейс (обновление)
* Окно сообщений в стиле старых мониторов: чёрный фон; принятые – зелёные, отправленные – красные, служебные/прочие – жёлтые; шрифт крупнее (12 pt, на Mac 13 pt).
* «Монитор приёма»: лампы **RX** (зелёная – идёт приём, жёлтая – декодирование) и **TX** (красная – передача), шкала уровня входа в дБ с предупреждением о перегрузке и водопад спектра 300…3000 Гц.

## Управление передачей (PTT / CAT)

Панель «Управление передачей» в окне программы. Порядок передачи: включить PTT → звук (в начале
звука идёт пауза «Задержка PTT/VOX») → выключить PTT. Если PTT включить не удалось, передача отменяется.
При «Прервать», ошибке звука и закрытии окна PTT снимается принудительно.

| Метод | Что делается | Типичные радиостанции |
|---|---|---|
| none | ничего (VOX или внешний PTT) | – |
| RTS / DTR / RTS+DTR | уровень «1» на линии COM-порта на время передачи; «Инверсия» меняет полярность | любой интерфейс с PTT по RTS/DTR (Digirig, SignaLink-подобные, самодельные) |
| ICOM | CI-V `FE FE <адрес> E0 1C 00 01/00 FD` | IC-7300 (94h), IC-705 (A4h), IC-7610 (98h), IC-9700 (A2h), IC-7100 (88h), IC-7851 (8Eh), IC-746PRO (66h), IC-706MKIIG (58h) и др.; адрес можно ввести вручную (CI-V Address в меню радио) |
| YAESU | `TX1;` / `TX0;` | FT-991/A, FTDX-101/10/3000/5000, FT-710, FT-891, FT-450D |
| YAESU-OLD | 5 байт `00 00 00 00 08` / `88` | FT-817/818, FT-857, FT-897, FT-100 |
| KENWOOD | `TX;`(или `TX0;`/`TX1;`) / `RX;` | TS-590, TS-480, TS-2000, TS-890, TS-570, TS-870 |
| ELECRAFT | `TX;` / `RX;` | K3, KX3, KX2, K4 |

Скорость порта должна совпадать с настройкой радио (подставляется типичная по методу).
Кнопка «Тест PTT» включает передатчик на 1 с без звука — используйте эквивалент нагрузки.
Нужен пакет `pyserial` (есть в requirements.txt).

**Не проверено:** команды составлены по открытым CAT-описаниям производителей, с реальными
трансиверами не тестировались (проверена только логика на имитации порта). Если на вашей модели
не работает — пришлите модель и вариант, поправим.

## Фильтр сообщений и цвета
Галочка «Фильтр: только сообщения для моего ID» (сохраняется в настройках, действует сразу): при включении
в чате остаются только сообщения, адресованные вашему ID (и подтверждения доставки для вас); чужие и маяки скрыты.
Без фильтра: адресованные вам — зелёные (жирным), чужие — голубые, отправленные — красные, служебные — жёлтые.

## Журнал сообщений (TXT)
Все сообщения (принятые, в том числе скрытые фильтром, повторы, маяки, отправленные, подтверждения и действия
сценариев) пишутся в текстовый файл `Документы/HFPagerApp/messages.txt` (Windows/macOS) с датой и временем.
Кнопка «Журнал (TXT)» в настройках открывает его в редакторе.

## Трансивер по CAT и сценарии
Кнопка «Трансивер / сценарии…» (панель PTT) открывает окно:
* **Связь:** протокол (ICOM/YAESU/YAESU-OLD/KENWOOD/ELECRAFT), COM-порт, скорость; «Как в PTT» копирует настройки PTT.
  Если порт совпадает с портом PTT (например CAT + PTT по RTS на одном интерфейсе), порт используется совместно.
* **Управление:** частота (МГц) и режим, кнопки диапазонов 160…6 м, шаги ±0.1/±1/±10 кГц, чтение частоты.
  Режимы: LSB USB CW CW-R AM FM RTTY USB-D LSB-D (D = цифровой/DATA, у ICOM — командой 1A 06).
* **Сценарии** (таблица, по умолчанию 12 строк, можно добавлять свои): «текст сообщения → действие».
  `*` в тексте — любое слово, значение подставляется в действие как `{1}`, `{2}`.

| Сообщение | Действие | Результат |
|---|---|---|
| `CNG BND 40` | `BND {1}` | диапазон 40 м (7.100 МГц LSB) |
| `SET FRQ 7.185 USB` | `FRQ {1} {2}` | 7.185 МГц, режим USB |
| `DIGI 20` | `BND {1}; MODE USB-D` | 20 м, цифровой режим |
| `FRQ UP 5` | `UP {1}` | частота +5 кГц |

Действия: `BND <м>`, `FRQ <МГц> [режим]`, `MODE <режим>`, `UP|DOWN <кГц>`, `WAIT <с>`; несколько — через «;».
Частоты по умолчанию для диапазонов заданы в `hfpager_rig.py` (BANDS).

Безопасность: выполнение сценариев по сообщениям **выключено по умолчанию** (галочка в окне); срабатывают только
сообщения, адресованные вашему ID, и только первый подходящий сценарий; в колонке «От ID» можно разрешить
конкретных отправителей (иначе команду может подать любой, кто знает ваш ID). Сценарии не включают передатчик.
Поле «Проверка» выполняет сценарий для введённого текста без отправителя. Если идёт передача, действие ждёт её конца.
Команды CAT составлены по документации и не проверены на реальных трансиверах.

## Отложенные сообщения (режим «QRU?»)
Кнопка «Отложенные сообщения…» открывает окно со списком «кому — текст». Если включена галочка и станция X
присылает вам (на ваш ID) сообщение `QRU?`, программа через ~2 с отправляет ей до 5 сообщений, ожидающих ID X
(после окончания вашей передачи/подтверждения). Если ничего нет — можно отвечать `QRU` (галочка). Текст запроса
меняется в окне. Повторный `QRU?` в течение 2 минут игнорируется.

Файл для интеграции с другими менеджерами: `Документы/HFPagerApp/outbox.txt` (путь можно изменить), UTF-8,
одна строка = одно сообщение, разделитель `|`:

    # комментарий
    10048|Привет, жду на 7.185
    5|Встреча завтра в 18:00

Файл можно редактировать вручную или дописывать из другой программы: приложение перечитывает его при изменении
и при каждом запросе. Отправленные строки удаляются из `outbox.txt` и дописываются в `outbox_sent.txt`:
`2026-11-04 23:58:08|10048|Привет, жду на 7.185`.

**Удаление после подтверждения.** Отложенное сообщение передаётся с запросом подтверждения доставки и удаляется из
`outbox.txt` (и дописывается в `outbox_sent.txt`) только после получения ACK от адресата. Время ожидания — поле
«Ждать подтверждение, с» (по умолчанию 60). Нет подтверждения — сообщение остаётся в очереди и уйдёт снова при
следующем запросе `QRU?`; повторная доставка того же текста у получателя помечается как повтор. Это работает, если
станция адресата отвечает подтверждением (в оригинальном HFPager — при запросе подтверждения).

## Windows 7 и старые процессоры
* **NumPy «built with baseline optimizations (X86_V2) but your machine doesn't support»** — NumPy 2.x требует процессор
  с SSE4.2/POPCNT (примерно 2009 г. и новее). Сборка теперь использует NumPy 1.24.x (`requirements.txt`: `numpy<2`),
  работающий и на старых процессорах.
* **Windows 7:** Python новее 3.8 на ней не запускается (отсутствуют системные DLL). Поэтому exe собирается на
  Python 3.8 (workflow выдаёт `HFPagerApp-windows-x64` и `HFPagerApp-windows-x86` — для 32-битных систем берите x86).
  На самой Windows 7 нужны Service Pack 1 и обновление **KB2999226 (Universal C Runtime)**, при ошибках с `api-ms-win-*.dll`
  или `VCRUNTIME140.dll` — «Распространяемый пакет Visual C++ 2015–2019» (x86/x64 по разрядности).
* Запуск из исходников на Windows 7: Python 3.8, `py -3.8 -m pip install -r requirements.txt`, `py -3.8 hfpager_app.py`.
